## 1. Dataset inspection

Three dialogue → note corpora were downloaded (`data/raw/`, registry and SHA-256s in
`data/MANIFEST.json`). Raw formats differ in every respect, which is why an importer exists:

| corpus | raw format | pairs | what one record is | licence |
|---|---|---|---|---|
| **ACI-Bench** (Yim et al., 2023) | JSON `{"data":[{"src","tgt","file"}]}`, 5 files | 67 / 20 / 40+40+40 | a *full* recorded encounter (`[doctor] … [patient] …`, ~1,300 words, ~50 turns) → a complete clinical note (CC / HPI / ROS / PE / RESULTS / A&P, ~420 words) | CC-BY 4.0 |
| **MTS-Dialog** (Ben Abacha et al., 2023) | CSV with embedded newlines, 4 files | 1,201 / 100 / 200+200 | a *short* dialogue snippet (`Doctor: … Patient: …`, ~65 words, ~6 turns) → **one section** of a note, labelled with a 20-value `section_header` (GENHX, FAM/SOCHX, PASTMEDICALHX, CC, ROS, MEDICATIONS, …) | CC-BY 4.0 |
| **DialogueSOAP** (omi-health, HF) | JSON **Lines** (not a JSON array), 3 files | 9,250 / 500 / 250 | a synthetic dialogue (~420 words, ~17 turns) generated by an LLM from a PMC case report → a SOAP note (`S:`/`O:`/`A:`/`P:`, ~245 words) | MIT (synthetic) |

Observed quirks that shaped the cleaning:

- ACI-Bench transcripts are ASR-style: lower-case, tokenised punctuation (`hi , andrew .`), speaker
  tags in brackets, occasionally `[patient_guest]`. Notes are ALL-CAPS section headers on their own line.
- MTS-Dialog has 131 one-word targets in train (`None.`, `Noncontributory.`, `Asthma.`) — legitimate
  section values, not corruption — and a handful of two-line "any known drug allergies? / No." dialogues
  that recur verbatim across its official splits.
- DialogueSOAP notes are long, dense and LLM-written; its `prompt` field is the generation prompt of the
  original authors and is kept in `metadata` but never shown to our model.

## 2. Dataset selection and role

All three are used, with distinct roles fixed by the project report:

| corpus | role | reason |
|---|---|---|
| ACI-Bench | **primary target task, headline test set** | the only corpus with real full encounters and complete notes; the FaCTS claim (fewer hallucinations at equal ROUGE) has to be shown here |
| MTS-Dialog | section-level supervision, second test set | in-domain, human-written, same provenance as ACI-Bench (MEDIQA-Chat 2023); teaches section writing cheaply |
| DialogueSOAP | training volume only | synthetic; the report forbids using it as the sole evaluation basis, so its test split is *reported* but is not a headline number |

## 3. Cleaning and standardization

`scripts/import_datasets.py` converts each corpus into one schema:

```json
{"id": "aci_bench_train_D2N002-virtassist", "dataset": "aci_bench", "split": "train",
 "source_dialogue": "...", "target_summary": "...", "metadata": {"file_id": "D2N002-virtassist"}}
```

Cleaning applied per record (identical for all corpora):

1. **Field mapping**: `src/tgt`, `dialogue/section_text`, `dialogue/soap` → `source_dialogue` /
   `target_summary`. Corpus-specific metadata is preserved (`file_id`; `row_id` + `section_header`;
   `prompt`) so nothing is lost and the MTS section is available as a task instruction.
2. **Whitespace normalisation**: outer `strip()`; internal newlines kept (turn boundaries and section
   breaks are meaning-bearing for both the model and the fact extractor). Speaker tags are *not*
   rewritten — the model must learn the real ASR style of the target task.
3. **Empty / null drop**: any record with an empty source or empty target is skipped and counted
   (`skipped` in the importer summary). None were found in the three corpora.
4. **Encoding**: everything is read and written as UTF-8; the audit scans for control characters
   (none found).
5. **Stable ids**: `<dataset>_<split>_<native id>` so every prediction, fact and metric can be joined
   back to its record without positional indexing.

Official splits are kept as delivered — nothing is re-split, so results stay comparable to the
published leaderboards.

## 4. Duplicates, unusable samples, leakage

`scripts/audit_dataset.py` (results: `reports/data_audit/data_audit.md`).

**Exact duplicates.** Normalised (whitespace-collapsed, lower-cased) source dialogues: 2 duplicate
sources inside MTS-Dialog train, 1 in test_sum_2023, none elsewhere. Duplicate *pairs*
(same source *and* target): 1 in MTS-Dialog train. Duplicate ids: 0.

**Near-duplicates.** 64-bit SimHash over 3-word shingles, banded candidate search, Hamming
distance ≤ 3. ACI-Bench: 0 pairs. DialogueSOAP: 0 pairs (9,250 synthetic dialogues are all
distinct). MTS-Dialog: 12 pairs, 3 within a split and 9 across splits — every one is the MTS-Dialog
design of re-using one dialogue for several section targets, listed in
`reports/data_audit/near_duplicates.jsonl`.

**Unusable samples.** Criteria: empty text, source < 5 words, target < 2 words, target identical to
source, control characters. Only the "target < 2 words" rule fires: 131 / 10 / 14 / 13 records in the
four MTS-Dialog splits, all one-word section values (`None.`, `Penicillin.`, `Noncontributory.`).
**Decision: keep them.** They are correct outputs for their section (writing `None.` under
MEDICATIONS when the patient takes nothing is the desired behaviour), the official test sets contain
the same kind of item, and dropping them from train would bias the model towards always producing
content. They are flagged in `data_audit.json` so the evaluation can report metrics with and without
them.

**Leakage.** Checked between the baseline mix (`baseline_train.jsonl` ∪ `baseline_val.jsonl`) and
all six test splits:

| check | result |
|---|---|
| id overlap train/val, train/test, val/test | 0 / 0 / 0 |
| exact source-dialogue overlap mix ↔ test | **0** after `make_baseline_split.py` dropped 3 MTS-Dialog train rows (`mts_dialog_train_901/926/989`, the recurring "any known drug allergies? / No." exchange) |
| exact target overlap mix ↔ test | 131 — all boilerplate one-word/one-line targets (`None.`, `No known drug allergies.`); not content leakage |
| near-duplicate sources mix ↔ test (Hamming ≤ 3) | 2: `mts_dialog_train_318`↔`test_chat_2023_96` (punctuation variant of the allergy exchange) and `mts_dialog_train_543`↔`test_sum_2023_78` (same dialogue, different section target) |
| `train_manifest.json` SHA-256 vs files on disk | match (train and val) |

The two near-duplicate test ids are flagged in the evaluation (`FLAGGED_TEST_IDS` in
`src/eval/run_eval.py`); their effect on a 400-item MTS test set is below reporting precision, and
the official test sets are not modified.

## 5. Train / validation / test preparation

`scripts/make_baseline_split.py` (seed 42) builds the Review 2 mix specified in
`REVIEW2_BASELINE.md` §4.1 and writes `train_manifest.json` with counts and SHA-256s:

| file | n | composition |
|---|---|---|
| `baseline_train.jsonl` | **4,265** | ACI-Bench train 67 + MTS-Dialog train 1,198 (1,201 − 3 dropped) + DialogueSOAP train 3,000 (random, seed 42) |
| `baseline_val.jsonl` | **220** | ACI-Bench val 20 + MTS-Dialog val 100 + DialogueSOAP val 100 |
| test (untouched, 6 files) | **770** | ACI-Bench 40+40+40, MTS-Dialog 200+200, DialogueSOAP 250 |

Why 3,000 of the 9,250 DialogueSOAP rows: enough to teach SOAP structure, while keeping the
2-epoch run inside a Kaggle 2×T4 budget; the full set triples training time for a synthetic corpus.
Records are shuffled once after mixing so that `group_by_length` batching in the trainer is the
only ordering effect. The same files were uploaded unchanged as the private Kaggle dataset
`hirthick17/medsum-fact-processed` and are what the adapter was trained on (SHA-256 verified by the
Kaggle kernel and by the audit).

## 6. Lengthy conversations

Lengths were measured in **Llama-3.1 tokens exactly as the trainer sees them** (system prompt +
task instruction + transcript rendered with the chat template, plus the note and the end-of-turn
token), using the tokenizer saved with the adapter:

| corpus | prompt tokens p50 / p95 / max | prompt + note p50 / p99 / max | > 4,096 (dropped from training) |
|---|---|---|---|
| ACI-Bench train | 1,619 / 2,411 / 3,635 | 2,195 / 4,129 / 4,405 | 1 (`D2N021-virtscribe`) |
| ACI-Bench test (3 splits) | 1,429–1,641 / 2,402–3,028 / 3,275 | 1,938–2,224 / 3,913–4,312 / 4,461 | 0 at inference (prompt only) |
| MTS-Dialog train | 169 / 533 / 2,254 | 193 / 1,157 / 3,681 | 0 |
| DialogueSOAP train | 688 / 794 / 946 | 1,050 / 1,292 / 1,491 | 0 |
| **baseline mix** | — | 992 / 1,991 / 4,405 | **1 of 4,265** |

Policy, in order of what was considered:

1. **Truncate the transcript** — rejected: the reference note still asserts facts from the cut
   part, so the model would be trained to hallucinate.
2. **Truncate the note** — rejected: the model learns to stop mid-note (exactly the failure mode we
   later measured as run-1 truncation).
3. **Chunk the dialogue** and summarise per chunk — deferred to Review 3 (it needs the fact table to
   merge chunks coherently; MODEL_PLAN.md Stage 0/1).
4. **Drop over-length training examples and keep the full context at inference** — adopted. The
   training window is 4,096 tokens (the largest that fits 2×T4 with the fused cross-entropy,
   REVIEW2_BASELINE.md §3.4); exactly one training example exceeds it. At inference the prompt is
   never cut (Llama-3.1 context is 128k), so all 770 test conversations are seen in full.

The prompt share of a training example is 0.73 (ACI-Bench) / 0.86 (MTS-Dialog) / 0.65
(DialogueSOAP): this is why loss is computed on the note tokens only (§4.4 of the baseline doc);
otherwise ~75% of the gradient would be spent learning to reproduce transcripts.

## 7. Basic clinical fact extraction (`src/cfe/`)

### 7.1 Design

A deterministic, dependency-free extractor that turns any transcript or note into a list of
**facts** with provenance. It is the Review 2 stand-in for the scispaCy + UMLS Stage 1 of
MODEL_PLAN.md and keeps the same schema, so the evaluation and the Review 3 prompt builder do not
change when the extractor is upgraded.

```
Fact = {category, text, canonical, polarity, certainty, temporality, experiencer,
        section, speaker, start, end, sentence_idx, value, unit, frequency, route, drug, subtype, trigger, is_class}
```

| required category | how it is recognised | canonical form |
|---|---|---|
| **Symptoms** | 146 canonical symptoms / signs, 684 surface forms (`short of breath`, `sob`, `can't breathe` → `dyspnea`) | lexicon canonical |
| **Medical history** | a condition mention in a history context: PMH / family / social section, or a historical trigger (`history of`, `years ago`, `known`, `s/p`), or a family experiencer; drug allergies (ALLERGIES section, `allergic to X`) | condition canonical (237 conditions, 1,037 surfaces) |
| **Diagnosis** | any other condition mention; `subtype="asserted"` when it sits in ASSESSMENT/PLAN/CC or next to a diagnostic cue (`diagnosed with`, `consistent with`, `likely`, …), otherwise `"mentioned"` | condition canonical |
| **Medications** | 357 generics with US brand names (`Lipitor` → `atorvastatin`) + 37 drug classes flagged `is_class` (`antibiotic`, `statin`) | generic name |
| **Dosages** | regex `number + unit` (mg, mcg, mL, units, puffs, tablets, %, …) with optional frequency (`twice a day`, `q6h`, `prn`) and route (`po`, `IV`, `topical`), attached to the nearest drug in the sentence (preceding within 80 chars, else following within 40) | `<drug> <value><unit>` |
| **Investigations** | 113 canonical labs / imaging / exam manoeuvres / scores, 1,143 surfaces (`a1c`, `hba1c`, `glycated hemoglobin` → `hemoglobin a1c`); vitals and lab **values** become `numeric` facts with `subtype = vital / lab / age / duration` | lexicon canonical |
| **Treatment / follow-up** | 18 canonical treatment types (surgery, injection, physical therapy plan, wound care, lifestyle modification, referral, hospital admission, discharge, medication management, …) with 1,671 surfaces, plus a regex for follow-up *timing* (`follow up in 4 weeks` → value 4, unit week) | canonical + value |
| **Negations** | NegEx/ConText-style assertion on every fact: pre-triggers (`denies`, `no`, `without`, `negative for`, `don't think`, …), post-triggers (`was ruled out`, `resolved`), pseudo-negations masked (`no increase`, `not only`), scope closed by `but / however / except`, 12-word window; plus **dialogue Q/A rule**: a bare `No.` from the patient negates the terms asked in the doctor's question sentence, a bare `Yes.` confirms them | `polarity = absent` |

Additional assertion attributes come for free from the same rule set: `certainty` (`possible`,
`rule out`, `?`, `side effects can include …` → uncertain), `temporality`, `experiencer`.

Text handling: the segmenter detects dialogue vs. note, splits dialogue into speaker turns
(`[doctor]`, `Doctor:`, `Guest_family:`), notes into sections (ALL-CAPS headers, `S:/O:/A:/P:`,
`HEADER: text`; MTS-Dialog sections come from `section_header` via `MTS_SECTION_MAP`), then into
sentences with character offsets. Lexicon matching is longest-match-wins across categories;
abbreviations of ≤ 3 letters (`CAD`, `CHF`, `DOE`) must appear in upper case so `as`, `pe`, `ms` in
prose never fire; short terms take no plural suffix.

### 7.2 Validation

- **Unit tests**: `tests/test_cfe.py` (14 tests: negation scope, pseudo-negation, post-negation, the
  dialogue Q/A rule, dosage/frequency attachment, sections and routing, vitals/labs/ages/durations,
  follow-up timing, provenance offsets, abbreviation casing, class flags) — all pass.
- **Manual spot-check**: 40 randomly sampled facts from ACI-Bench test reference notes
  (`reports/data_audit/cfe_samples.md` has the rendered samples). Before the fixes: 35/40 fully
  correct, 38/40 correct at entity+polarity level. The five errors (a `DOE` match inside "does", a
  drug in the ALLERGIES section counted as a medication, `9-month-old` given unit *years*, a
  hypothetical side-effect listed as a present symptom, `has had` marking a current complaint as
  historical) led to the abbreviation-plural, allergy-section, age-unit and hypothetical-cue rules now
  in the code; the first four are fixed, the temporality one is a known limitation.
- **Corpus-level sanity** (`reports/data_audit/cfe_stats.md`): 82–85% of the entities extracted from an
  ACI-Bench reference note are also extracted from its transcript (72–79% for MTS-Dialog, whose notes are
  written from a wider context than the snippet). Negation rate of reference-note facts is 13–14%
  (ACI-Bench, ROS-heavy) / 18–26% (MTS-Dialog) / 6% (DialogueSOAP), matching the styles of the corpora.
  Dosage facts are linked to a drug name 83–93% of the time in ACI-Bench notes.
- **Speed**: 120–150 ms per ACI-Bench record (dialogue + note), ~10 ms per MTS-Dialog record; the full
  12,108-record corpus takes ~9 minutes on the laptop CPU.

### 7.3 Known limitations (carried to Review 3)

Lexicon recall is bounded by the lists (no UMLS linking, no unseen drug names); multi-word symptom
phrasing outside the lists falls back to the generic `pain`/`swelling` entry; temporality from
`has had` over-fires on current complaints; no coreference (`it hurts` is not linked to the knee).
Every one of these is addressed by the scispaCy + UMLS + negspaCy Stage 1 planned for Review 3,
which slots in behind the same `Fact` schema.
